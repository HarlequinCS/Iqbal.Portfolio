## 2. What was implemented

### Technical SEO
- **Clean, unique URLs:** `/`, `/about`, `/work/veritas`, `/work/hrsb-one`, `/work/roadsense`. Any `*.html` address and `/index.html` now 301 to the clean URL; `/work` and `/work/` 301 to `/#work`; `/404` is a real 404. All internal links use the clean form, so no link causes a redirect hop.
- **Unique title and meta description on every page**, each naming "Saiful Iqbal". Titles are 56–60 characters; descriptions 148–170.
- **`<meta name="robots">`** on every page: `index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1` (lets Google show large image previews and full snippets). The 404 page is `noindex, follow`.
- **Self-referencing absolute canonicals** that match `og:url`. `lang="en"` was already set.
- **Open Graph and Twitter Card metadata** on every page: `og:site_name`, `og:type` (profile/article), `og:image` with size and alt text, `og:locale` (`en_MY`), `article:author`/`published_time`/`modified_time` on case studies, plus Twitter title, description, image and alt text.
- **Headings:** exactly one `<h1>` per page and no skipped levels (checked automatically). The homepage `<h1>` now starts with "Saiful Iqbal."
- **Breadcrumbs:** visible breadcrumb trails (Saiful Iqbal / Work / VERITAS) on case studies and the About page, matched by `BreadcrumbList` markup.
- **Author bylines** on case studies link to the About page with `rel="author"`. Profile links use `rel="me"`.
- **Favicon** at `/favicon.ico`, plus the existing PNG icons and the web manifest on every page.

### Crawling and indexing
- `robots.txt`: allows everything except `/api/`, keeps CSS/JS/fonts/images crawlable so Google can render pages, and points to the sitemap.
- `sitemap.xml`: generated by `tools/build.py` from each page's canonical tag. Absolute URLs, `<lastmod>` from git history, and an image entry for the portrait on the homepage and About page. Every URL in it returns 200 (checked).
- PDFs send `X-Robots-Tag: noindex, nofollow`. They are still downloadable from the site.
- `/api/`, `/docs/`, `/tools/`, dotfiles, `README.md` and draft files are never deployed, or they return 404.

### On-page and content
- **Keywords** come from your real work. Primary: *Saiful Iqbal*. Branded variants: *Muhammad Saiful Iqbal*, *Muhammad Saiful Iqbal Abdul Rani*, *Saiful Iqbal developer / software engineer / cybersecurity / portfolio / Malaysia / Johor*. Topic terms: web vulnerability assessment, OWASP Top 10, Laravel HR and payroll system, Malaysian statutory payroll (EPF, SOCSO, EIS, PCB), Android road hazard app. Each name form appears where it reads naturally; nothing is stuffed or hidden.
- **New `/about` profile page** (about 900 words of original text): who you are, what you've built, security work, education, how you work, and a six-question FAQ. Every statement comes from your existing site or CV.
- **Internal links:** homepage → About (About section and footer); every page's footer → About; About → each case study, credentials and contact; case studies → About (byline) and the homepage (breadcrumb).
- **Images:** the portrait was renamed from `intro.webp` to `saiful-iqbal.webp`, with alt text "Portrait of Saiful Iqbal (Muhammad Saiful Iqbal Abdul Rani)". All images already had alt text, set dimensions and lazy loading below the fold.

### Performance (Core Web Vitals)
- **LCP:** fonts are self-hosted (IBM Plex, latin + latin-ext, about 165 KB in total, downloaded only for the characters a page uses) with the main font preloaded, which removes the Google Fonts stylesheet and two third-party connections. The hero portrait is preloaded with `fetchpriority="high"`.
- **CLS:** every image has width and height set; fonts use `font-display: swap` from the same origin.
- **INP:** no new JavaScript was added. The effects are already loaded as on-demand modules.
- **Caching:** CSS and `js/main.js` URLs now carry a content hash (`?v=…`), so each deploy is picked up at once instead of after Cloudflare's cache expires.
- **Measured:** server response time (TTFB) through Cloudflare was 60–85 ms for `/`, `/about` and `/work/veritas`; compressed HTML is 6–16 KB.

### Security
- The CSP is tighter: `style-src` and `font-src` are now `'self'` only (Google Fonts removed).
- No internal paths, API routes or server details appear in the sitemap, metadata or structured data.
- The structured data uses your public site email, not the personal email or phone number from the CV.

## 4. Structured data

All pages use one linked `@graph` with stable IDs (`https://saifuliqbal.io/#person`, `#website`, `#team-chendawan-ventures`), so Google sees every page describing the same person.

| Page | Types |
|---|---|
| `/` | `WebSite`, `ProfilePage` (mainEntity → Person), `BreadcrumbList`, `Person` (full), `Organization` (Team ChendAwan Ventures, founder → Person) |
| `/about` | `AboutPage` + `ProfilePage`, `BreadcrumbList`, `FAQPage` (6 questions, matching the visible text), `Person` (reference) |
| `/work/*` | `Article` (author/publisher → Person), `WebPage`, `BreadcrumbList`, `SoftwareApplication` or `MobileApplication` (creator → Person) |

The full `Person` entry includes: name, alternate names (Saiful Iqbal, Muhammad Saiful Iqbal, Iqbal), portrait `ImageObject`, description, job title and occupations, Kluang, Johor, MY, employer, UiTM (linked to its Wikipedia page), knowsAbout, languages, the diploma and 10 certifications as `EducationalOccupationalCredential`, 3 awards, and `sameAs` → LinkedIn and GitHub.

**Not used, on purpose:**
- `Product`, `Review` and `AggregateRating`: nothing is sold here, and ratings would be fabricated.
- Offers or prices on the software entries: VERITAS's pricing isn't published on this site.

**What to expect from Google:**
- `FAQPage` is valid markup, but Google currently shows FAQ rich results only for well-known government and health sites.
- In the Rich Results Test, `SoftwareApplication` may show "missing offers/aggregateRating". That only means no software rich result. It isn't an error with the page.

**How it was validated:** JSON syntax and every `@id` reference were checked on the live pages by `tools/audit.py`, and property names were checked against schema.org. Google's Rich Results Test and the Schema.org validator need a browser, so run them yourself (section 6).

## 6. Google Search Console: readiness and your steps

**Ready:** the site is HTTPS-only with one preferred host (`https://saifuliqbal.io`); robots.txt allows crawling; the sitemap is public, valid and lists only indexable 200 pages; canonicals are consistent; no important page is noindexed.

**Not done:** verification and sitemap submission. I don't have access to your Google account or your DNS (Cloudflare), so nothing has been submitted.

Steps:
1. Go to https://search.google.com/search-console and choose **Add property → Domain**, then enter `saifuliqbal.io`.
2. Google shows a `google-site-verification=…` TXT record. In Cloudflare: **DNS → Records → Add record**, type `TXT`, name `@`, paste the value, save. Back in Search Console, click **Verify**. It can take a few minutes.
3. **Sitemaps** → submit `https://saifuliqbal.io/sitemap.xml`.
4. **URL Inspection** → inspect `https://saifuliqbal.io/`, then **Test live URL** and check that the page is available, the canonical is `https://saifuliqbal.io/` and the rendered screenshot looks right. Click **Request indexing**. Repeat for `/about`, then the three case studies.
5. Run https://search.google.com/test/rich-results on `/` (expect Profile page and Breadcrumb) and on `/about`.
6. Run https://pagespeed.web.dev/ on `/` for mobile Core Web Vitals. Field data appears only once the site has enough real visitors.
7. Optional: in https://www.bing.com/webmasters, choose **Import from Google Search Console** to cover Bing, DuckDuckGo and Yahoo.
8. In Cloudflare, check **Security → Bots**: "Bot Fight Mode" should not block verified bots. If URL Inspection's live test fails, look here first.
